# Light: A Go Port of Hugging Face Candle

**Date:** 2026-04-17
**Status:** Draft — awaiting approval
**Goal:** Full-feature Go port of Hugging Face Candle that runs complex ML models on CUDA GPUs and CPU with a Go-idiomatic API.

---

## 1. Goals & Non-Goals

### Goals
- Run real transformer models (LLaMA family, BERT, Whisper, Stable Diffusion, CLIP) end-to-end on CUDA GPU with performance within 2x of Candle/PyTorch.
- Full CPU fallback that produces identical (bit-exact for integer dtypes, numerically close for floats) results.
- Go-idiomatic API: explicit errors, options pattern, `io.Reader` loaders, `context.Context` for cancellation, generics where they aid type safety.
- Support all CUDA-supported dtypes: `F16`, `BF16`, `F32`, `F64`, `U8`, `I8`, `U32`, `I32`, `U64`, `I64`, plus quantized `Q4_0`, `Q4_1`, `Q5_0`, `Q5_1`, `Q8_0`, `Q8_1`, `Q2K`..`Q8K` (GGUF).
- Automatic GPU memory management via `runtime.AddCleanup` finalizers.
- Autograd (tape-based) for training and fine-tuning workflows.
- >80% test coverage, including CPU↔CUDA parity tests for every op.
- Rich examples folder covering every supported model and feature.

### Non-Goals (v1)
- Metal / ROCm / WebGPU backends (CUDA + CPU only for v1; architecture leaves room).
- Multi-GPU / distributed training.
- Beating cuBLAS/cuDNN performance with hand-rolled kernels (we'll use vendor libs where Candle does).
- ONNX export.
- Mobile deployment.

### Licensing
Candle is Apache-2.0 / MIT dual-licensed. Reused `.cu` files will carry original copyright headers and a `NOTICE` file will credit upstream.

### 3.1 `dtype.DType`

```go
type DType uint8
const (
    F16 DType = iota

    F32
    F64
    U8
    I8

    U64
    I64
    // Quantized (GGUF)

)
func (DType) Size() int             // bytes per element
func (DType) IsFloat() bool
func (DType) IsQuantized() bool
```

### 3.2 Generic Numeric Constraint
```go
type Numeric interface {
    ~float32 | ~float64 | ~int8 | ~int16 | ~int32 | ~int64 |
    ~uint8 | ~uint16 | ~uint32 | ~uint64
}
// Half / BF16 are opaque structs wrapping uint16; handled via DType runtime dispatch, not generics.
```

### 3.3 `shape.Shape` & `shape.Strides`
Immutable value types; shape ops (reshape/permute/broadcast) return new values. Contiguity inferred from strides.

### 3.4 `device.Device`
```go
type Device interface {
    Kind() Kind          // CPU | CUDA
    Ordinal() int        // 0 for CPU, gpu index for CUDA
    String() string
    sameAs(Device) bool
}
func CPU() Device
func CUDA(ordinal int) (Device, error)  // errors if nvcc/runtime missing
```

### 3.5 `storage.Storage`
Opaque byte buffer with attached `Device`, `DType`, element count, and a cleanup. Never accessed directly by users — owned by `Tensor`.

### 3.6 `tensor.Tensor`
```go
type Tensor struct { /* unexported */ }

func New[T dtype.Numeric](data []T, shape []int, dev device.Device) (*Tensor, error)

// Shape ops (cheap — share storage where possible)

func (*Tensor) Permute(dims ...int) (*Tensor, error)
func (*Tensor) Contiguous() (*Tensor, error)

// Ops (allocate new tensors)

// ... dozens more

// Data movement
func (*Tensor) To(dev device.Device) (*Tensor, error)
func ToSlice[T dtype.Numeric](t *Tensor) ([]T, error)
```

Errors, not panics. Nil-safe where sensible.

## 4. Backend Abstraction & Op Dispatch

### Strategy
Each op is a **public Go function** in `ops/` (or method on `*Tensor`) that:
1. Validates shapes/dtypes/devices.
2. Allocates output storage.
3. Dispatches to the per-backend, per-dtype kernel via an internal registry:

```go
type Kernel func(ctx *KernelContext) error
// registry keyed by (OpName, DeviceKind, DType)
```

CPU kernels live in `kernels/cpu/`, CUDA kernels in `kernels/cuda/`. The registry is populated at package init.

### No silent fallback
Attempting a GPU op without the `cuda` build tag (or without an available GPU) returns an explicit error. Examples assert `device.Kind() == CUDA` to satisfy your checkpoint criterion.

## 5. Dtype Polymorphism

Two layers:

1. **Runtime dispatch** (`DType` enum) — for internal kernel selection and heterogeneous operations (e.g., casts). Required because `F16`/`BF16`/quantized types don't fit clean Go generics.
2. **Compile-time generics** (`[T Numeric]`) — for type-safe user-facing entry points: `New[T]`, `ToSlice[T]`, `Scalar[T]`. These assert at runtime that `T` matches the stored `DType`.

`.cu` files use C++ templates:
```cpp
template<typename T> __global__ void add_kernel(const T* a, const T* b, T* out, size_t n);

#define INSTANTIATE(T) template __global__ void add_kernel<T>(const T*, const T*, T*, size_t);
INSTANTIATE(float); INSTANTIATE(double); INSTANTIATE(__half); INSTANTIATE(__nv_bfloat16);
INSTANTIATE(int8_t); INSTANTIATE(int32_t); INSTANTIATE(int64_t); INSTANTIATE(uint8_t);
```

A single CGo `add_kernel_launch(dtype, ...)` wrapper fans out to the typed instantiation via a switch on `DType`.

## 6. CUDA Integration

### Build tags
All CGo files: `//go:build cuda`. Pure-Go CPU build (`go build ./...`) must succeed without CUDA toolkit installed.

### CGo layout
```
internal/cudart/
├── runtime.go       // cudaMalloc/Free/Memcpy/Stream
├── cublas.go        // gemm, gemv, gemmEx (mixed-precision)
├── cudnn.go         // conv, pool, softmax fast paths
├── kernels.go       // our custom kernels' launch wrappers
└── build.go         // cgo directives (CFLAGS, LDFLAGS)
```

`build.go`:
```go
//go:build cuda
// #cgo CFLAGS: -I${SRCDIR}/../../kernels/cuda/include
// #cgo LDFLAGS: -L/usr/local/cuda/lib64 -lcudart -lcublas -lcublasLt -lcudnn -L${SRCDIR} -llight_kernels
import "C"
```

### Kernel compilation — PTX + driver JIT strategy
`go generate ./kernels/cuda/...` invokes `nvcc -ptx -arch=compute_80` to produce **virtual-architecture PTX** (one `.ptx` file per `.cu` translation unit). PTX is `//go:embed`ed into the Go binary under `kernels/cuda/ptx/`.

At runtime, the first use of each kernel calls `cuModuleLoadDataEx` on the embedded PTX; the **CUDA driver JITs PTX → SASS for the local GPU** and caches the result under `~/.nv/ComputeCache` (driver-managed; persists across runs). No `nvcc` needed at runtime.

Rationale for `compute_80` (Ampere) baseline:
- Has tensor cores, bf16, modern atomics — covers all ops we need in v1.
- Forward-compatible: JITs to Ada (sm_89), Hopper (sm_90), **Blackwell (sm_120 — your RTX 5060)**, and any future arch.
- Broadest runtime reach (also runs on A100/T4/RTX 30xx/40xx).

For kernels that genuinely need newer ISA (e.g., FP8 tensor-core MMAs on Hopper/Blackwell), we emit a second PTX variant at `compute_90` and pick the higher one at load time if the local GPU supports it.

If **`nvrtc` is available at runtime**, we additionally expose an opt-in `LIGHT_RUNTIME_COMPILE=1` path that compiles `.cu` source (also embedded) for the exact local SM via nvrtc — useful for profiling / new arch features. Off by default.

Build: `go generate ./...` produces PTX → `kernels/cuda/ptx/*.ptx` (embedded). `go build -tags cuda ./...` produces the final binary. No separate `.a`/`.so` required.

### cuBLAS / cuDNN usage
- **Gemm** (matmul, linear): cuBLAS `cublasGemmEx` / `cublasLtMatmul` (supports F16/BF16/F32/F64/TF32, tensor cores).
- **Conv / Pool / Softmax fast path**: cuDNN.
- **Elementwise, reductions, LayerNorm, RoPE, SDPA, attention variants, quantization**: reused/adapted from Candle's `candle-kernels/src/*.cu`.

### Reusing Candle kernels
Candle's kernels live in `candle-kernels/src/` (unary, binary, affine, indexing, reduce, softmax, rope, mmul_quant, etc.). We copy these into `kernels/cuda/src/` with a `CANDLE-UPSTREAM` header tag and retain upstream copyrights. Where Candle's launch assumptions differ from ours, thin wrappers adapt.

## 7. Autograd (PyTorch-style, define-by-run)

Dynamic computation graph built implicitly during the forward pass, not a linear tape.

### Core types
```go
// Every Tensor carries autograd metadata when RequiresGrad is true.
type Tensor struct {
    // ...
    requiresGrad bool
    grad         *Tensor        // accumulated leaf gradient (leaves only)
    gradFn       *FunctionNode  // nil for leaves; non-nil for ops that produced this tensor
    outputNr     int            // which output of gradFn produced this tensor
    version      uint64         // in-place mutation counter (version-counter trick)
}

// A Function is a user-implementable op with a forward and backward.
// Built-in ops (Add, MatMul, Softmax, …) each implement this.
type Function interface {
    Forward(ctx *Context, inputs ...*Tensor) ([]*Tensor, error)
    Backward(ctx *Context, gradOutputs []*Tensor) ([]*Tensor, error)
}

// Context persists from forward to backward for a single application of a Function.
type Context struct {
    SavedTensors []*Tensor
    Attrs        map[string]any   // scalar args (axes, keepdims, …) saved for backward
    NeedsGrad    []bool           // per-input
}

// FunctionNode = one node in the dynamic DAG.
type FunctionNode struct {
    fn       Function
    ctx      *Context
    nextEdges []Edge            // one per *input* of the forward call; points upstream
    numOut   int
}

type Edge struct {
    Node      *FunctionNode    // upstream; nil if that input was a leaf/no-grad
    OutputNr  int              // which output of Node produced that upstream tensor
}
```

### Flow
1. Forward: calling an op like `a.Add(b)` calls `Apply(AddFn{}, a, b)`. `Apply`:
   - Runs the forward kernel.
   - If any input `requiresGrad`, allocates a `FunctionNode`, links `nextEdges` to inputs' `gradFn`, and sets the output tensor's `gradFn` to this node.
2. Backward: `out.Backward()` (or `out.BackwardWith(gradOutput)`):
   - Topological sort of `FunctionNode`s reachable from `out` via `nextEdges`.
   - Reverse-order traversal. For each node, calls `fn.Backward(ctx, accumulated_grad_outputs)`.
   - Resulting input grads are accumulated into the upstream nodes' slots (sum if visited from multiple paths).
   - Leaf tensors accumulate into `tensor.grad`.

### Semantics (v1 choices)
- **Reverse-mode only** (no forward-mode / JVP).
- **First-order gradients only** (no `create_graph=True`); second-order deferred to a later phase.
- **Views in autograd**: a view's backward walks to its base and accumulates at the base's location. Base↔view version-counter tracking catches the "saved tensor mutated after forward" case and returns a clear error.
- **In-place ops**: allowed but bump the version counter; backward asserts a saved tensor's version matches. Mismatch → descriptive error.
- **Grad accumulation**: default is sum-on-grad (matches PyTorch). `tensor.ZeroGrad()` resets.
- **`no_grad` scope**: `ctx := autograd.NoGrad(ctx)` disables graph construction inside the scope; essential for inference hot paths.
- **Hooks** (tensor.RegisterHook / module hooks): deferred to Phase 8.

### Go-idiomatic surface
- `autograd.Enable(t *Tensor)` and `t.RequiresGrad()` / `t.SetRequiresGrad(bool)` helpers.
- All ops return `(*Tensor, error)`; backward errors propagate the same way.
- Registering a new differentiable op = implement `Function` and register once at package init. The op registry from §4 merely gains a "grad" companion slot.

Implementation phase: Phase 4, but the scaffolding (`Context`, `Function`, `FunctionNode`, `Edge`, `Tensor` grad fields) is reserved in Phase 1 so we don't need later refactoring.

## 8. Memory Management

### Finalizers
Every `storage.Storage` registers `runtime.AddCleanup` at construction. Cleanup:
- CPU: no-op (Go GC collects the slice).
- CUDA: `cudaFree(ptr)` on the storage's stream, then stream sync.

We prefer `AddCleanup` over legacy `SetFinalizer` (Go 1.24+).

### Views
Shape ops (reshape / permute / slice / narrow) return a new `Tensor` sharing the underlying `*Storage`. `Storage` uses an atomic refcount; cleanup fires only when refcount hits 0.

### Pinned host memory
Optional for fast host↔device transfers: `device.CUDA(i).AllocPinned(bytes)`. Allocated via `cudaHostAlloc`, freed via `cudaFreeHost` on cleanup.

### Pools
Per-device caching allocator (free-list by size bucket) to avoid `cudaMalloc` churn. Tunable/disable-able.

## 9. Model I/O

### safetensors
Pure Go. Memory-mapped on CPU; streaming copy to GPU. Supports lazy tensor loading.

### GGUF
Pure Go reader. Quantized weights loaded as `Tensor` with `DType=Q4_0` (etc.) and dedicated dequantization kernels (CPU + CUDA; reused from Candle).

### Hugging Face Hub
`hub/` package: HTTP-based downloader using Go stdlib. Cache dir `~/.cache/huggingface/hub/`. No git LFS.

## 10. Testing Strategy

- **Unit tests per op**: CPU kernel correctness.
- **Parity tests per op**: Run on CPU and CUDA, compare (atol/rtol by dtype). Skipped if CUDA unavailable; CI job has both.
- **Property tests**: Broadcasting, reshape, permute invariants via randomized shapes.
- **Golden tests**: Store reference outputs from Candle/PyTorch for a fixed prompt, compare our inference.
- **Coverage gate**: `go test -cover`, threshold ≥80% per package, enforced via a `scripts/coverage.sh` check.
- **GPU-only assertions**: Example programs fail loudly if they silently fall back to CPU.

## 13. Phased Roadmap (high-level)

Each phase ends with a full checkpoint: compile (`-tags cuda` and without), tests pass, coverage ≥80% for new code, examples run, GPU actually used on CUDA path.

- **Phase 0 — Environment & scaffolding.** Verify CUDA toolkit, scaffold package tree, feature tracker, kernel build pipeline.
- **Phase 1 — Core tensor (CPU).** DType, Shape, Storage (CPU), Tensor, basic ops (add, sub, mul, div, neg, matmul naive), shape ops, finalizers.
- **Phase 2 — CUDA backend.** cudart bindings, CUDA Storage with finalizer, memcpy to/from host, basic element-wise kernel infra, CPU↔CUDA parity tests.
- **Phase 3 — Full op coverage.** All elementwise / reductions / broadcasting / indexing / slicing / concat / cast / softmax / layernorm / rmsnorm — CPU + CUDA. cuBLAS gemm integration. Quantized dequant kernels.
- **Phase 4 — NN & transformers.** Linear, Embedding, Conv2d (cuDNN), LayerNorm, RMSNorm, SDPA, RoPE, KVCache, MHA, GQA. Autograd.
- **Phase 5 — Loaders.** safetensors, GGUF, HF Hub client.
- **Phase 6 — Tokenizers.** BPE, SentencePiece, WordPiece (pure Go).
- **Phase 7 — Models.** LLaMA-2/3, Phi, Gemma, Mistral, BERT, Whisper, CLIP, Stable Diffusion, T5.
- **Phase 8 — Training.** Optimizers (SGD, AdamW), LR schedulers, gradient clipping, fine-tuning examples.
- **Phase 9 — Quantization.** GPTQ, AWQ loading; quantization utilities.
- **Phase 10 — Polish.** Perf tuning, docs, benchmarks, release notes.

The **step-by-step implementation plan** (written after this design is approved) will decompose each phase into ~5-15 discrete steps, each with its own checkpoint.

## 14. Resolved Decisions

1. **`CUDA_PATH`** — default `/usr/local/cuda`, overridable via `CUDA_PATH` env var. ✓
2. **Half-precision on CPU** — software emulation (F16 and BF16 implemented as `uint16`-backed storage with software conversion ops). CPU and CUDA match bit-width-wise. ✓
3. **CUDA streams** — single default stream per device in v1. Multi-stream deferred to Phase 10. ✓
4. **Autograd scope (v1):**
   - Reverse-mode only; no forward-mode JVP. ✓
   - First-order gradients only; no `create_graph=True` (second-order deferred). ✓
   - In-place ops allowed via version counter (PyTorch-style). ✓
   - Hooks (tensor/module) deferred to Phase 8. ✓
5. **Candle kernel reuse** — vendored into `kernels/cuda/src/third_party/candle/`, file-by-file with upstream copyright headers retained and top-level `NOTICE` file attributing the project. ✓
6. **GPU targeting** — `compute_80` PTX baseline for broad reach; `compute_90` PTX variant for kernels needing Hopper/Blackwell ISA. Driver JITs at first load; cache persists in `~/.nv/ComputeCache`. `nvrtc` path optional via `LIGHT_RUNTIME_COMPILE=1`. Primary target machine: RTX 5060 (sm_120). ✓
7. **CPU-only build must succeed** without CUDA toolkit present — enforced by build tags. ✓
